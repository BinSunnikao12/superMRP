## 0. 一句话定位

**MVP-1（1 个月内）**：单据点、单层 BOM、静态数据 → 跑通 MRP 核心算法（含多角贸易、呆滞物料、采购优先级）→ Web 端展示净需求表。

**目标人群**：1 个据点的计划员，手动上传 Excel 主计划 + 静态基础资料，点击"运行 MRP"，看到含优先级拆解的净需求结果。

## 1. MVP-1 范围（1 个月内必须完成）

### 1.1 输入

| 输入 | 来源 | 说明 |
|------|------|------|
| **主计划 A** | Excel 导入 | 料件、数量、开工时间 |
| **BOM** | 静态 JSON | 父子物料 + 用量（最多 3 层） |
| **基础资料** | 静态 JSON | 料件 → 补给策略、采购单位批量、最小起购量、提前期 |
| **库存** | 手动录入 | 静态可用库存 |
| **领用在制** | 手动录入 | 静态未完工量 |
| **多角在途** | 手动录入 | 静态未入库量 |

> 注：V0.3 之前计划"采购单位批量"作为算法的一部分，但**飞书文档该段被划线**——确认**MVP-1 不实现**批量规则。

### 1.2 输出

- **净需求表**（每条料件）：净需求数量、开工时间、完工时间、补给策略、**优先级拆解**（自制工单 vs 采购需求 vs 委外订单）

### 1.3 MVP-1 限制

- **只 1 个据点**（默认 LG）
- **BOM 最多 3 层**（A→B→C）
- **A=10个以下子件**
- **总料件 < 5000**
- **不需要 T+1 走批**（手动点"运行"）
- **不需要对接鼎捷/MES**（全部手动输入）
- **不实现**采购批量/最小起订量修正（已划线剔除）

### 1.4 核心算法清单（基于飞书文档 2 + 3 张图）

#### 1.4.1 净需求计算

```typescript
// 时间倒推
预计开工时间 = 预计完工时间 - 生产提前期/采购提前期
预计完工时间（头层） = 主计划开工时间
预计完工时间（下阶） = 上一层开工时间

// 数量计算
净需求[头层] = 毛需求 - 领用在制 - 库存 - 多角在途
净需求[下阶] = 上层净需求 × BOM用量 - 领用在制 - 库存 - 多角在途
```

#### 1.4.2 自制物料优先级

```
对自制物料（B=50、C=100）：
  1. 优先匹配在制生产订单的余量
     例：B 的工单余量为 20 → B 用 20 抵消
         C 的工单余量为 30 → C 用 30 抵消
  2. 剩余部分（B=30、C=70）按 BOM 向下分解
  3. 向下分解时优先以该工单的备料明细部分分解为下阶需求
```

**算法图示（飞书原图）**：

```
       净需求 B=100
            ↓
   ┌─ B 下阶毛需求 ─┐
   │ B1=100 (×1)    │ B2=200 (×2)    │ B3=300 (×3)
   └────────────────┴─────────────────┴───────────────┘
            ↓
   ┌─ B 下阶可用供给 ──────────┐
   │ 领用在制 B1=20  B2=30  B3=60│
   │ 库存数量   B1=100 B2=50  B3=60│
   │ (先消耗领用在制,再消耗库存)  │
   └────────────────────────────┘
            ↓
       B1=0  B2=120  B3=180
```

#### 1.4.3 采购物料优先级（V0.3 新增）

```
对采购物料（D=100）：
  拆分为:
    - 自制工单 D=30（依净需求方法拆解）
    - 采购需求 D=70
```

**算法图示**：

```
       采购件 D=100
            ↓
   ┌─ 自制工单 D=30 ─┐  ┌─ 采购需求 D=70 ┐
   │ 依上述净需求方法 │  │ (外购请购单)   │
   │ 拆解下阶物料     │  │                 │
   └──────────────────┘  └─────────────────┘
```

> 注：实际 100% 看，文档 2 划线的"采购单位批量"段被剔除，意味着 D=100 时**不再向上取整到 150**。MVP-1 按 100 计算。

#### 1.4.4 多角贸易/呆滞物料处理（V0.3 新增）

```
LG 采购需求 S=1000
        ↓
  是否存在多角？
   ┌─ 是 ──────────────┐  ┌─ 否 ─────────┐
   │ GX 自制需求 S=800   │  │ GN 净需求 S=200 │
   │ (S1=800, S2=400,   │  │ → 结束         │
   │  S3=1600)           │  │                 │
   └─────────────────────┘  └─────────────────┘
```

**含义**：
- 当某据点（LG）的某物料无需求但其他据点（GX）有需求时，触发"多角贸易"——把 LG 的库存调拨给 GX
- V0.3 简化：MVP-1 只需识别"多角可能性"并打标记，**实际调拨由人工决策**

## 4. 算法例子（验收用）

基于飞书文档 2 的例子 + 3 张算法图：

### 例 1：B 物料的下阶分解（图 1）

```
输入:
  A 在 T1 时刻生产 100 件
  BOM: A -> B(1)
  B 的 BOM: B -> B1(1) + B2(2) + B3(3)
  基础资料:
    B: 自制
    B1/B2/B3: 略
  库存/在制:
    B1: 领用在制=20, 库存=100
    B2: 领用在制=30, 库存=50
    B3: 领用在制=60, 库存=60

输出:
  B 净需求 = 100 (头层)
  B 下阶毛需求: B1=100, B2=200, B3=300 (按 bom 用量 × B 净需求)
  B 下阶可用供给: 先领用在制再库存
  最终净需求: B1=0, B2=120, B3=180
```

### 例 2：D 采购物料的优先级（图 2）

```
输入:
  D 净需求 = 100
  D 基础资料: 补给策略 = 采购

输出:
  拆分为:
    - 自制工单 D=30 (依净需求方法拆解下阶)
    - 采购需求 D=70
```

### 例 3：多角贸易（图 3）

```
输入:
  LG 采购需求 S=1000

处理:
  判断是否多角?

  是 → GX 自制需求 S=800 (S1=800, S2=400, S3=1600)
  否 → GN 净需求 S=200 → 结束

输出:
  LG S=1000
  GX S1=800, S2=400, S3=1600
```
