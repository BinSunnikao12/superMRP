## 0. 一句话定位

**集团 MRP（Material Requirements Planning）系统**：从 5 个据点（LG、YN、QU、FN、GX）的主生产计划出发，按 BOM 逐层分解物料需求，扣除库存/在制/在途后生成净需求，并按补给策略（自制/外购/委外）下达为工单/请购单/委外单，**目标替代现有的手工 Excel MRP**。

### 灵魂（来自文档 1 原文）
> **实现集团内部需求一步到最底层的成本中心/供应商**

### 三大业务痛点（来自文档 4 原文）
1. 手工 Excel 算 1000+ 工单需数日 → 计划滞后
2. 5 据点 ERP 账套独立 → 跨据点协同困难、资源无法全局统筹
3. 与 MES 不同步 → 库存/在制数据失真 → 停工待料 / 库存积压

## 3. 核心算法（来自文档 2 · 最关键的部分）

### 3.1 输入（V0.1 第一阶段 MRP 运算的输入）
| 输入 | 来源 | 说明 |
|------|------|------|
| 主计划 A | 5 据点 ERP | 按时间序列拉平，不分据点，作为基准 |
| 库存量 | 库存系统 | 当前可用库存 |
| 领用在制 | 工单系统 | 工单备料领出未入库的备料用量 |
| 多角在途 | 多角贸易模块 | 多角贸易发出但未入库数量 |
| BOM | 基础资料 | 父子件 + 用量 |
| 基础资料 | 鼎捷 ERP | 补给策略、采购单位批量、最小起订量、生产提前期 |

### 3.2 主计划获取（算法 step 1）
```
从 LG/YN/QU/FN/GX 各据点获取主计划数据
  ↓
不分据点，按时间顺序排列
  ↓
得到 料件 A 的时间序列主计划数组
```

### 3.3 第一层毛需求分解（算法 step 2）
```
对 A 的每个时间点：
  - 从工单备料明细分解出第一层毛需求
  - 例：A 在 T1 时刻数量为 100 → B=100, C=150, D=200（依 BOM）
  - 调鼎捷基础资料取 B/C/D 的：
    * 补给策略（外购/自制/委外）
    * 采购单位批量（D=150）
    * 最小起订量（E=500）
    * 生产提前期 / 采购提前期
```

### 3.4 净需求计算（算法 step 3，最核心）

#### 3.4.1 时间倒推
```
第一层（B/C/D）：
  预计开工时间 = 预计完工时间 − 生产提前期/采购提前期
  预计完工时间 = 主计划 A 的开工时间

下阶物料：
  预计开工时间 = 预计完工时间 − 生产提前期/采购提前期
  预计完工时间 = 上一层计划的开工时间
```

#### 3.4.2 数量计算
```
第一层净需求 = 毛需求 − 领用在制 − 库存 − 多角在途
              例：B=100−0−50−0 = 50, C=150−0−50−0 = 100, D=200−0−100−0 = 100

下阶物料净需求 = 上层物料净需求 × BOM 用量 − 领用在制 − 库存 − 多角在途
```

#### 3.4.3 批量规则（Lot Sizing）
```
若 D 维护了采购单位批量（D=150）：
  D 净需求 = 50  → 显示为 150（向上取整倍数）
  D 净需求 = 200 → 显示为 300

若 E 维护了最小起订量（E=500）：
  E 净需求 < 500 → 按 500 算
```

#### 3.4.4 优先级处理（自制物料）
```
对自制物料（B=50、C=100）：
  1. 优先匹配在制生产订单的余量
     例：B 的工单余量为 20 → B 用 20 抵消
         C 的工单余量为 30 → C 用 30 抵消
  2. 剩余部分（50-20=30, 100-30=70）按 BOM 向下分解
  3. 向下分解时优先以该工单的备料明细部分分解为下阶需求
```

### 3.5 数据同步与异常处理（V0.1 简版）
- **数据同步**：与鼎捷 ERP（基础资料/库存/工单）+ MES（工单执行进度）按 T+1 同步
- **异常处理**：
  - 主计划变更 → 重新跑 MRP
  - 库存不一致 → 标记并通过 MES 实时校对
  - 多角在途超时 → 提示并冻结相关净需求

## 4. 数据模型（V0.1 骨架）

```
┌─────────────────────────────────────────────────────────────┐
│ 据点 (Site)        LG / YN / QU / FN / GX                   │
├─────────────────────────────────────────────────────────────┤
│ 基础资料 (Material)                                          │
│   - 料件代码 (GD01, GD16, ...)                               │
│   - 物料名称、单位                                           │
│   - 补给策略：外购 / 自制 / 委外                             │
│   - 采购单位批量、最小起订量                                  │
│   - 生产提前期、采购提前期                                    │
├─────────────────────────────────────────────────────────────┤
│ BOM (父-子-用量)                                              │
│   - A → B(1) + C(1.5) + D(2)                                │
│   - B → E(2) + F(0.5)                                        │
│   - ...无限层级                                             │
├─────────────────────────────────────────────────────────────┤
│ 主计划 (MasterPlan)                                          │
│   - 料件代码 (V0.1 默认 A)                                   │
│   - 数量、开工时间、完工时间                                  │
│   - 据点（合并后可不分）                                     │
├─────────────────────────────────────────────────────────────┤
│ 库存表 (Inventory)        库存量 / 安全库存                  │
│ 领用在制 (WIP)            工单备料领出未入库                  │
│ 多角在途 (InTransit)      多角贸易发出未入库                  │
├─────────────────────────────────────────────────────────────┤
│ MRP 运算结果 (MRPResult)                                     │
│   - 料件 / 层级 / 净需求数量 / 开工时间 / 完工时间           │
│   - 补给策略 + 建议动作（工单/请购单/委外单）                │
├─────────────────────────────────────────────────────────────┤
│ 建议动作 (SuggestedAction)                                   │
│   - 工单（自制）                                             │
│   - 请购单（外购）                                            │
│   - 委外单（委外）                                            │
└─────────────────────────────────────────────────────────────┘
```

## 5. 接口骨架（V0.1）

### 5.1 数据拉取（从 ERP / MES 拉，向量 V0.1 走 T+1 批量）
| 来源 | 接口 | 频率 |
|------|------|------|
| 鼎捷 ERP | 基础资料 / BOM / 库存 / 工单 / 主计划 | T+1 凌晨 |
| MES | 工单执行进度 / 在制状态 | T+1 凌晨 |
| 多角贸易模块 | 多角在途 | T+1 凌晨 |

### 5.2 数据下发（V0.1 单向，下发到 ERP）
| 输出 | 接口 | 频率 |
|------|------|------|
| 鼎捷 ERP | 工单 / 请购单 / 委外单 | 手动确认后下发 |

### 5.3 用户操作（V0.1 Web 端）
- 主计划导入/审批
- MRP 触发运算、查看结果
- 净需求审核、下达
- 多据点统一切换

## 6. 非功能需求（V0.1 必须）

### 6.1 性能（文档 5 数据）
- 起步：**30 万行/次** 单次 MRP 运算
- 扩展：**150 万行/次** 平滑扩展
- 单次 MRP 运算耗时 ≤ 30 分钟（30 万行场景）

### 6.2 架构（文档 5 关键词）
- 云服务器 + 读写分离 + 三库分离
- 多据点数据隔离（每据点独立 schema 或独立库）
- 历史记录保存（MRP 运算快照可追溯）

### 6.3 安全
- 角色权限控制（5 个角色）
- 据点级数据隔离（采购员只能看自己据点）
- 审计日志（谁在何时下达了什么）

## 9. 风险与建议

### 9.1 风险
- **需求文档 80% 是半成品**——避免直接进入开发，先做需求澄清
- **鼎捷 ERP 接口未确认**——技术对接风险最高
- **手工 MRP → 系统 MRP 切换**——计划员适应成本高
- **多据点数据一致性**——业务规则歧义

### 9.2 建议
1. **在 V0.1 先做算法 POC**：单一据点 + 静态数据 + 核心算法正确性验证
2. **需求澄清会议**：把第 8 节 8 个待补项过一遍
3. **技术预研**：先验证文档 5 的架构方案，确认 30 万行/30 分钟 是否可达
4. **分阶段上线**：V0.1 仅 1 据点试运行，V0.2 再扩展
