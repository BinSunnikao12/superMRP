# raw_base 断点续传设计

## 目标

`npm run pull:raw-base` 因网络、平台超时或手工停止而中断后，保留已经写入
`raw_base` 的数据，并在下次运行时从各站点最后成功页的下一页继续。

## 方案

- 五个站点并行，每个站点内部顺序分页，确保页码断点是连续的。
- `raw_base_pull_checkpoint` 每站点、每接口保存一条断点：同步模式、固定时间窗口、
  总行数、总页数、批大小、最后成功页、累计行数、首次启动时间和状态。
- 恢复时复用原来的 `last_pull_time` 与 `upper_pull_time`，保证分页数据集不漂移。
- 每页先 UPSERT 数据，再推进断点。若两步之间崩溃，最多重复一页；UPSERT 保证幂等。
- 页面请求自动重试并指数退避。重试耗尽后标记本站点失败，不推进正式增量水位。
- 全量完成后，用断点中的首次启动时间清理源端已删除的旧行，再核对本地行数。
- 成功后把断点标记为 `completed`，并将窗口上界写入 `pull_state`。

## 兼容性

程序启动时自动创建断点表，现有 Docker 数据库无需手工迁移；初始化 SQL 同步补充表结构。
启用功能前已经中断的历史任务没有可靠页码，第一次仍从第 1 页开始，但已有数据通过
UPSERT 保留。从本版本开始产生的中断均可续传。
