# MRP 管理工作台设计

## 目标

把数据同步、运行状态与净需求信号集中到一个制造计划工作台，使用户可以用五基地样本快速验证，也可以直接发起正式全量同步。

## 页面与交互

- 默认进入 MRP 工作台，保留同步监控、数据总览、运行日志和数据字典页签。
- 提供“每基地、每表最多 1000 条”和“全量拉取其他模块”两个互斥任务入口，均不包含 `raw_base`。
- 后端启动独立拉取进程，页面轮询任务状态，显示当前基地、接口、行数和最近日志。
- 基地切换后读取 MySQL 当前快照，展示物料级需求、供给和缺料信号。

## 当前计算边界

当前为单层快速预览：

`净需求 = MAX(0, 毛需求 + 安全库存 - 可用库存 - 可用在制 - 特殊工单供给)`

毛需求按需求数量与 QPA 汇总；在途和在验作为采购信号单列，不擅自冲减净需求。损耗率、批量取整、提前期和多级 BOM 递归留给正式计算引擎，页面明确显示这一边界。

## 可靠性

- 服务端拒绝重复同步任务和非法模式。
- 样本模式通过 `PULL_ROW_LIMIT=1000` 复用正式拉取器，保持同一套字段映射、分页和入库逻辑。
- 拉取失败由现有同步日志记录；旧快照不因单个接口失败而清空。
- 页面输出数据全部进行 HTML 转义，接口限制基地白名单和最大预览行数。

## 验证

- TypeScript 构建、ESLint 与 `git diff --check`。
- 实测同步状态、非法模式和净需求预览 API。
- 浏览器验证默认路由、100 行预览渲染及关键指标布局。
