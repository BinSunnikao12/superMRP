# 同步三方数量校验设计

## 成功标准

模块同步只有同时满足以下条件才记录为 `ok`：

1. 拉取结束时重新查询的源接口总数；
2. 本轮实际分页拉取行数；
3. 本轮替换完成后的 MySQL 作用域行数；

三者必须一致。样本模式比较 `min(源端总数, 样本上限)`，并单独标记为“样本一致”，不能冒充全量校验。

## 数据保护

- 分页数据先写成新批次，不立即删除旧快照。
- 拉完后再次调用源接口取得当时总数，避免只使用开始第一页的旧总数。
- 先校验新批次 MySQL 行数，再在事务中删除旧批次。
- 删除后再次统计最终作用域行数；不一致则回滚删除并清除失败的新批次。
- 源端总数在分页期间或最终校验前变化时，本轮失败，旧快照继续可用。

## 日志

`pull_log` 增加 `source_rows`、`db_rows`、`verification_status`。Admin 运行历史分别显示源端总数、实际拉取、MySQL 数量和“三方一致/样本一致/校验失败/未校验”。历史记录没有校验数据时明确显示“未校验”。

## 验证

完成 TypeScript 构建、类型检查、页面脚本语法检查和本地数据库字段迁移。由于用户的旧版全量进程正在运行，本轮不并发启动数据任务；新规则从下一次同步开始生效。
