1项目总览与架构

本项目是一个 APS (Advanced Planning and Scheduling) 高级排产系统，用于制造业企业的 MRP（物料需求计划）计算。系统从 Oracle ERP 数据库读取工单、BOM、库存等基础数据，经过 MRP 核心运算后，生成物料需求计划、采购需求明细、生产需求等结果，最终输出为 Excel 报表并同步写入 MySQL 数据库。

核心业务场景：乐歌股份（LocTek）多基地生产排程 — 支持乐歌(LG)、越南(YN)、曲阜(QU)、广西(GX)、奉化(FN) 五个生产基地，每个基地独立运行 MRP 计算。

4运算层详解 (compute/)

4.1 compute.py — MRP 核心引擎 (serve 类)

初始化 __init__()

构造函数中一次性加载所有数据（约 20 个数据源），并创建副本用于后续计算（remain_dict_copy、cj_dict_copy、gd01_copy），因为计算过程中库存会被逐条扣减，副本保留原始值用于报表展示。

核心方法调用链

# 外部调用入口 excel.f(site) → compute.serve(site).calculate() # calculate() 内部流程 calculate() ├── 遍历 need（工单需求） │ └── sss(v) # 处理单条需求 │ ├── sss() 内部 │ │ ├── remain_operation(v) # 库存扣减 + 净需求计算 │ │ ├── 损耗率 + 批量取整 │ │ └── aaa(v) # BOM递归展开 │ │ └── methods.xxxx() # 创建子件需求 │ │ └── remain_operation() # 递归扣减 │ │ └── aaa() # 继续展开下阶 │ └── 追加到 self.l │ ├── 遍历 safetystock（安全库存需求） │ └── sss(v) # 同上 │ ├── 计算"总装发出数量"（已发出工单的毛需求汇总） │ └── 生成库存汇总 self.r（多余库存/多余在制等）

关键方法说明

方法运算逻辑
calculate() 主入口。遍历工单需求列表，构造需求字典（含毛需求=BOM用量×需求数量），调用 sss() 处理。之后处理安全库存需求，最后汇总发出数量和库存报告。
sss(v) 单条需求处理。调用 remain_operation() 扣减库存→计算净需求→应用生产损耗率→批量取整→设置齐套数初始值(∞)→追加到结果列表→若非外购且有净需求则调用 aaa() 递归展开BOM。
remain_operation(v) 核心库存扣减。按"可用库存→可用在制→GD01可用工单数"顺序扣减毛需求，剩余即为净需求。同时计算人工工时、设置各前置时间、计算预计开工日期（完工日期-前置时间），调用假期调整。
aaa(m) BOM 递归展开。先检查工单级BOM（gd_bom_dict），与标准BOM对比后选择使用；然后调用 methods.xxxx() 展开子件并递归。
hoilday_func(v) 假期调整。如果工单的[预计开工日,预计完工日]区间与假期有重叠，将预计开工日向前推移假期天数，确保开工日落在非假期工作日。

4.2 methods.py — 运算辅助函数

函数运算逻辑
demand(warehouses, needs) 多仓库存扣减算法。按字典序遍历可用库存（库存→在制→GD01），逐个扣减直到需求满足或全部耗尽。返回 (净需求, 剩余库存)。
xxxx(bom, n, m, s) BOM 展开核心。遍历 BOM 子件列表，为每个子件创建需求记录：计算毛需求=QPA×数量、递归调用 remain_operation() 扣减库存、计算齐套数（取子件可用库存/BOM用量的最小值）、若子件非外购且有净需求则递归调用 aaa() 继续展开。
compare_data(data1, data2) BOM 结构比较。按[主件,下阶,QPA]排序后逐项比较，用于判断工单级BOM与标准BOM是否一致。

6核心运算逻辑深度分析

6.1 毛需求计算

毛需求 = 主件需求数量 × (QPA分子 / QPA分母)
即：工单需求量 × BOM单位用量

在 calculate() 中构造需求字典时计算。子件展开时，毛需求 = 子件QPA × 父件净需求（methods.xxxx() 中 jj["毛需求"] = jj["QPA"] * n）。

6.2 净需求计算 — 多级库存扣减

净需求 = max(0, 毛需求 - 可用库存 - 可用在制 - GD01可用工单数)

核心在 methods.demand() 函数中实现，按固定顺序遍历三个"仓库"逐个扣减：

def demand(warehouses, needs): for warehouse, stock in warehouses.items(): # 顺序: 可用库存 → 可用在制 → GD01 if stock >= needs: warehouses[warehouse] = stock - needs needs = 0 break else: warehouses[warehouse] = 0 needs -= stock return (max(0, needs), warehouses)
关键设计：库存扣减是消耗性的——同一条料号在多条需求中，库存会被逐条递减（remain_dict[item] 在每次 remain_operation() 后更新），确保不会重复分配库存。

6.3 生产损耗率与批量取整

净需求(最终) = ceil(净需求 × (1 + 损耗率/100) / 生产批量) × 生产批量
向上取整到生产批量的整数倍（当前生产批量 IMAE017 固定为1）

在 sss() 和 methods.xxxx() 中均有此计算，确保生产数量满足批量要求和损耗补偿。

6.4 前置时间与排程计算

预计开工日期 = 预计完工日期 - 前置时间

前置时间 = MySQL配置值(leadtime_map[站点, 成本中心编码])
    （或 = 固定生产前置 + 变动生产前置 + QC前置 + 累计前置，当无配置时使用ERP标准值）

特殊规则：乐歌喷塑车间模块化标记物料 → 前置时间 +1 天
        虚拟件(X类) → 前置时间 = 0

6.5 假期调整算法

hoilday_func(v) 在前置时间计算后执行：

# 1. 检查工单[预计开工日, 预计完工日]是否与假期区间重叠 if 开工日 <= 假期结束日 and 完工日 >= 假期开始日: overlap = 假期 # 2. 计算需要前移的天数 重叠天数 = 假期结束日 - 完工日 # 如果为负则取0 前移天数 = (假期结束日 - 假期开始日) - 重叠天数 + 1 # 3. 开工日向前推移 预计开工日期 = 预计开工日期 - 前移天数

6.6 BOM 递归展开算法

这是 MRP 的核心递归逻辑，在 aaa() → methods.xxxx() → aaa() 中形成递归链：

成品工单需求
→
sss() 处理顶层
→
aaa() 展开BOM
→
xxxx() 创建子件
→
remain_operation() 扣库存
→
aaa() 继续展开
→ ...

工单级 BOM 优先逻辑（gd_bom）：

  • 先检查 gd_bom_dict 中是否有该料号的工单级 BOM
  • 若有，用 compare_data() 比较工单级BOM与标准BOM是否一致
  • 若不一致（说明该工单使用了修改后的BOM），优先使用工单级BOM展开
  • 工单级BOM按未交量逐条消耗，消耗完后再使用标准BOM
  • 虚拟件（主件类别="X"）的父跟单码取上一层的父跟单码，BOM用量=QPA×父件BOM用量

6.7 齐套数计算

齐套数 = min(子件使用库存 / 子件BOM用量)
初始值为无穷大(inf)，逐层递归取最小值

在 methods.xxxx() 中：如果父件齐套数 > 子件使用库存/BOM用量，则更新为子件值。最终齐套数表示该工单在当前库存下能配套生产的最大套数。

6.8 工单供给分配

在 excel.py 第351-357行，对生产需求按日期排序后分配工单供给：

for index, row in grouped.iterrows(): if zgd[料号] > 净需求总和: 工单供给 = 净需求总和 # 供给充足，全部满足 zgd[料号] -= 净需求总和 # 扣减可用供给 else: 工单供给 = zgd[料号] # 供给不足，全部分配 zgd[料号] = 0 # 供给耗尽

供给量是消耗性的——按日期先后顺序分配，先到先得。

6.9 合计欠料计算

合计欠料[料号] = 累计净需求（同料号多条需求累加）
在 remain_operation() 中: self.total_demand[item] += v["净需求"]

6.10 人工工时计算

人工工时 = 标准人工工时(IMAE051) × 净需求
子件标准人工工时 = base["IMAE051"]（子件料号的单位标准工时）
主件标准人工工时 = main_base["IMAE051"]（主件料号的单位标准工时）
